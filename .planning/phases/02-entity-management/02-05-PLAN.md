  <name>Task 3: Implement Lifecycle Transition State Machine</name>
  <files>internal/ea/validation.go, internal/ea/service.go, web/src/components/ea/DynamicFormBuilder.vue</files>
  <action>
    **Backend State Machine (internal/ea/validation.go):**
    1. Add ValidateLifecycleTransition function with transition rules:
       ```go
       func ValidateLifecycleTransition(currentStatus, newStatus string) error {
           validTransitions := map[string][]string{
               "Proposed":   {"Active", "Deprecated"},
               "Active":     {"Deprecated", "Retired"},
               "Deprecated": {"Retired"},
               "Retired":    {}, // Terminal state - no transitions allowed
           }
           allowed, exists := validTransitions[currentStatus]
           if !exists {
               return fmt.Errorf("invalid current lifecycle status: %s", currentStatus)
           }
           for _, status := range allowed {
               if status == newStatus {
                   return nil
               }
           }
           return fmt.Errorf("invalid lifecycle transition: %s → %s", currentStatus, newStatus)
       }
       ```

    2. Integrate into UpdateEntity method in internal/ea/service.go:
       - Before updating lifecycle_status_id, fetch current entity
       - Get current lifecycle status name and new status name
       - Call ValidateLifecycleTransition(currentStatus, newStatus)
       - Return 400 error if transition invalid

    3. Add domain-specific transition rules if needed (per CONTEXT.md decision):
       - Proposed → Active may require approval (optional enforcement)
       - Active → Retired may require justification
       - Store transition_reason in entity attributes or audit log

    **Frontend Validation (web/src/components/ea/DynamicFormBuilder.vue):**
