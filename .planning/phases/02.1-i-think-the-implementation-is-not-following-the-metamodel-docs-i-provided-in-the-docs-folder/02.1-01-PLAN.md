Rewrite migration 009 to implement the metamodel docs exactly.

**Scope:**
1. **Preserve infrastructure:** Keep ea_teams table, admin user creation, RBAC permissions, validation queries
2. **Replace CI types:** Delete all 52 existing CI type INSERTs, replace with exactly 28 CI types matching metamodel docs
3. **Replace relationship types:** Delete all 22 existing relationship type INSERTs, replace with relationships matching directional graph

**CI type naming convention:**
Use format `EA.{Domain}-{EntityType}` where:
- Domain: Strategy, Business, Application, Data, Technology, Infrastructure, Security, Governance
- EntityType: Name from metamodel docs (code-friendly variant acceptable)
- Examples: `EA.Strategy-Objective`, `EA.Business-BusinessCapabilityL1`, `EA.Application-BusinessApplication`

**Entity hierarchy implementation:**
For hierarchical entities (e.g., Business Capability L1 → L2):
- Create separate CI types for each level
- Add `parent_id` optional attribute for child entities
- Use `decomposes` relationship type for hierarchy connections

**CI type structure per entity:**
```sql
INSERT INTO ci_type_definitions (name, description, required_attributes, optional_attributes, created_by)
VALUES (
    'EA.{Domain}-{Name}',
    '{Description from docs}',
    '[{"name":"name","type":"string"},{"name":"description","type":"string"},{"name":"owner","type":"string"}]'::jsonb,
    '{Domain-specific optional attributes as JSONB array}',
    (SELECT id FROM users WHERE username = 'admin' LIMIT 1)
)
```

**Relationship type structure:**
For each directional relationship from docs (e.g., `Objective -->|drives| Initiative`):
```sql
INSERT INTO relationship_types (name, description, forward_label, reverse_label, allowed_source_types, allowed_target_types, cardinality_source, cardinality_target, bidirectional, attributes, created_by)
VALUES (
    '{relationship_label}',
    '{description}',
    '{forward_label}',
    '{reverse_label}',
    ARRAY['EA.{SourceDomain}-*'],
    ARRAY['EA.{TargetDomain}-*'],
    'many',
    'many',
    {true if bidirectional else false},
    '{{"description": "{explanation}", "archimate_concept": "{concept}"}}'::jsonb,
    (SELECT id FROM users WHERE username = 'admin' LIMIT 1)
)
```

**Mapping directional graph to relationships:**
From `docs/02-metamodel-relationships.md`:
- `Objective -->|drives| Initiative` → relationship type: `drives` (Objective → Initiative)
- `BusApp -->|supports| BC_L1` → relationship type: `supports` (BusinessApplication → BusinessCapabilityL1)
- `Subsystem -->|deployed on| Compute` → relationship type: `deployed_on` (ApplicationSubsystem → ComputePlatform)
- `ITComponent -->|enforces| Control` → relationship type: `enforces` (ITComponent → Control)
- etc.

**Bidirectional handling:**
Most relationships are bidirectional in EA practice. Use:
- `bidirectional: true` for most relationships
- `forward_label` and `reverse_label` for clear semantics

**Preserve sections from original migration:**
- SECTION 0: Admin user creation (keep)
- SECTION 1: EA Teams table (keep)
- SECTION 2: EA CI Type Definitions (REPLACE)
- SECTION 3: EA Relationship Type Definitions (REPLACE)

- Relationship type count: Should match count from 02-metamodel-relationships.md

**Update down migration:**
Ensure `009_add_ea_metamodel.down.sql` properly deletes all CI types and relationship types created.

**Reference original migration:**
Keep attribute JSONB structure patterns from original migration (validation rules, enums, etc.) for consistency.

GROUP BY SUBSTRING(name FROM 'EA\.([^.]+)\-')
