# Phase 02.1: EA Metamodel Implementation Verification - Context

**Gathered:** 2026-02-21
**Status:** Ready for planning

## Phase Boundary

Verify that the EA metamodel implementation (migration 009) matches the metamodel specification in `docs/01-metamodel-structure.md` and `docs/02-metamodel-relationships.md`. Correct any deviations through full rollback and recreation of EA CI types and relationship types to achieve exact compliance with the documented metamodel.

## Implementation Decisions

### Documentation Location
- Metamodel specification is located in `docs/01-metamodel-structure.md` (entity hierarchy) and `docs/02-metamodel-relationships.md` (relationship graph)
- These two Mermaid diagrams define the authoritative EA metamodel that migration 009 must implement

### Expected Structure
- **Entity Types**: The 8-domain tree hierarchy in 01-metamodel-structure.md defines ALL required entity types — exact match required
- **Relationship Types**: The directional graph in 02-metamodel-relationships.md defines ALL required relationship types — exact match required
- **Naming Conventions**: CI type names should match the conceptual entity names from docs (e.g., "Business Capability L1"), but code-friendly variants are acceptable (e.g., "BusinessCapabilityLevel1", business_capability_l1)
- **Attribute Schema**: Each entity type from the docs must have a corresponding CI type definition with appropriate JSONB attributes

### Verification Approach
- **Scope**: Comprehensive 1:1 check — every entity type and relationship from the docs must exist in the implementation
- **Method**: Compare each entity type and relationship from metamodel diagrams against migration 009's seeded data
- **Output Format**: Structured verification report (markdown) organized by domain showing:
  - Entities/relationships from docs (expected)
  - Entities/relationships in migration 009 (actual)
  - Gap analysis (missing, extra, or mismatched items)
  - Detailed before/after comparison tables

### Gap Resolution
- **Primary Strategy**: Fix implementation to match documentation — non-negotiable compliance with metamodel docs
- **Deletion Policy**: Full rollback and recreate — delete all non-compliant EA CI types and relationship types from migration 009, then recreate from scratch to match docs exactly
- **Data Safety**: No production EA entities exist yet — safe to delete and recreate CI type definitions without data loss
- **Scope**: Only affects CI type definitions and relationship type definitions — EA teams table and other infrastructure can remain

### Verification Documentation
- **Location**: Create standalone markdown document at `docs/ea-metamodel-verification.md`
- **Format**: Detailed comparison report including:
  - Before/after comparison tables for each domain
  - Gap lists showing missing, extra, and mismatched items
  - Explanation of each correction made
  - Final confirmation that implementation matches metamodel docs

## Specific Ideas

- The metamodel follows ArchiMate 3.x principles across 8 domains: Strategy, Business, Application, Data, Technology, Infrastructure, Security (NIST), Governance
- Entity hierarchy is tree-structured: e.g., Business Domain → Business Capability L1 → Business Capability L2
- Relationship graph shows directional semantics: e.g., Objective "drives" Initiative, Application "supports" Business Capability, Subsystem "deployed on" Compute Platform
- Migration 009 currently seeds EA teams and some CI types, but may not match the exact structure from docs
- Verification should check both CI type definitions AND relationship type definitions
